### 3. TelemetryEventBridge ✅

**Effort:** 2-3 hours
**Tests:** 20 passing (116 assertions)
**Status:** COMPLETED 2025-11-18

#### Implementation Details

- **Automatic Span Creation:**
  - Listens to all lifecycle events
  - Creates appropriate spans based on event type
  - Manages span lifecycle (start/end)
  - Tracks active spans to prevent leaks

- **Supported Operations:**
  - LLM requests (before/after with timing)
  - Tool execution (before/after/error)
  - Guard checks (checking/passed/violated/fallback)
  - Memory operations (loading/loaded)
  - Stream operations (started/completed)

- **Configuration:**
  - `trace_llm` - Enable/disable LLM tracing
  - `trace_tools` - Enable/disable tool tracing
  - `trace_guards` - Enable/disable guard tracing
  - `trace_memory` - Enable/disable memory tracing
  - `trace_streams` - Enable/disable stream tracing
  - `trace_mcp` - Enable/disable MCP tracing

#### API Example

```php
// Register event bridge for automatic tracing
EventManager::instance()->listen(new TelemetryEventBridge());

// All operations now automatically create spans via events
agent('bot')->prompt('Hello');
// Events fired → Bridge creates spans → Exported to backend
```

### 4. MCP Client Support ✅

**Effort:** 6-8 hours
**Tests:** 69 passing (315 assertions)
**Status:** COMPLETED 2025-11-19

#### Implementation Details

- **McpClient:**
  - Full MCP protocol v2024-11-05 implementation
  - JSON-RPC 2.0 communication
  - Tool discovery and execution
  - Resource discovery and reading
  - Prompt discovery and retrieval
  - Event-driven lifecycle hooks

- **Transports:**
  - **StdioTransport** - Process-based MCP servers (subprocess communication)
  - **HttpSseTransport** - HTTP Server-Sent Events transport

- **Tool Integration:**
  - **McpToolAdapter** - Wraps MCP tools as Pagent tools
  - Automatic schema conversion (MCP → Anthropic/OpenAI)
  - Parameter validation
  - Seamless integration with existing tool system

- **MCP Events (10 total):**
  - **Connection Events (5):** Initiating, Established, Failed, Disconnecting, Disconnected
  - **Tool Events (5):** Discovering, Discovered, Calling, Called, Error

- **Error Handling:**
  - `McpException` - Base exception
  - `McpConnectionException` - Connection failures
  - `McpProtocolException` - Protocol violations
  - `McpTimeoutException` - Operation timeouts

#### API Examples

```php
// Connect to MCP server via stdio
$transport = new StdioTransport('npx -y @modelcontextprotocol/server-filesystem /tmp');
$client = new McpClient($transport);
$client->connect();

// Discover and list tools
$tools = $client->discoverTools();
foreach ($tools as $tool) {
    echo "Tool: {$tool['name']}\n";
}

// Execute a tool
$result = $client->callTool('read_file', ['path' => '/tmp/test.txt']);

// Register event listeners
$client->on('mcp_connection_established', function($event) {
    echo "Connected! Server: {$event->serverInfo['name']}\n";
});

$client->on('mcp_tool_called', function($event) {
    echo "Tool {$event->toolName} executed in {$event->durationMs}ms\n";
});
```

## Architecture Highlights

### Event-Driven Telemetry

The integration of Events + TelemetryEventBridge represents a **clean architectural pattern**:

1. **Events Fire** - Agent/LLM/Tool operations dispatch lifecycle events
2. **Bridge Listens** - TelemetryEventBridge receives events
3. **Spans Created** - Bridge automatically creates appropriate OpenTelemetry spans
4. **Exporters Handle** - Spans exported to configured backend (Jaeger, Zipkin, etc.)

This decouples observability concerns from core agent logic, making the codebase more maintainable and testable.

### MCP Integration

The MCP implementation follows the **adapter pattern**:

- `McpClient` - Protocol layer (JSON-RPC 2.0)
- `McpTransport` - Transport abstraction (Stdio, HTTP SSE)
- `McpToolAdapter` - Bridges MCP tools into Pagent's tool system
- MCP Events - Lifecycle hooks for monitoring and debugging

This allows seamless integration with the growing MCP ecosystem while maintaining Pagent's existing tool architecture.
